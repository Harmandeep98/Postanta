Social Media Manager API

Instagram automation backend — scheduled posts and a ManyChat-style rule engine that auto-replies to comments and DMs based on keyword matches.

Overview

All request/response bodies are JSON. Errors are returned as { "error": "message" } with a 4xx/5xx status. Successful writes return 201 (create) or 204 with no body (delete).

EnvironmentBase URL
Localhttp://localhost:3000
StagingCoolify staging URL — separate Meta app, safe to test against
ProductionCoolify prod URL — live Instagram accounts, real DMs get sent
Staging uses its own META_APP_ID, so testing automations there never touches real Instagram traffic.

Authentication

Every route below except /health and /webhooks/* requires a Clerk session token as a Bearer token:

HEADER 
Authorization: Bearer <clerk_session_jwt>

For local testing, generate a token from the Clerk Dashboard → Users → select user → "Create session token". /webhooks/* routes skip Clerk auth entirely but verify a signature instead (Meta HMAC or Svix, see below) — never call them directly yourself.

Connecting an Instagram account is a two-step OAuth dance, not a single API call:

StepRouteWhat happens
1GET /auth/instagramOpen in a browser (not Postman/curl) while logged in. Redirects to Facebook's OAuth dialog.
2GET /auth/instagram/callbackMeta redirects here after consent. Server exchanges the code for a long-lived token, fetches the IG business account(s), upserts SocialAccount rows, then redirects to FRONTEND_URL.

Automations (Rule Engine)

A rule fires when a webhook event matches its triggerType + keyword, then performs one actionType. Three combinations are valid:

TriggerActionDescription
COMMENT_KEYWORDSEND_DMComment contains keyword → send a private DM to the commenter
COMMENT_KEYWORDREPLY_COMMENTComment contains keyword → reply publicly under the comment
DM_KEYWORDREPLY_DMIncoming DM matches keyword → reply in the same thread

Other fields:

FieldValuesMeaning
matchTypeCONTAINS / EXACT / STARTS_WITHHow triggerKeyword is matched against the incoming text
postIdIG post ID or nullnull = applies to all posts. Ignored (forced null) for DM_KEYWORD rules
messageTemplatestringResponse text. Supports {{first_name}}
replyOncePerUserboolean, default trueEnforced at the DB level via a unique constraint — a user triggers a rule at most once, ever
cooldownMinutesint, default 60Skip if the same user triggered the same rule again within this window
Mismatched trigger/action pairs are rejected with 400 — e.g. REPLY_COMMENT requires triggerType: COMMENT_KEYWORD.

Webhooks

Called by Meta / Clerk — not by your frontend or Postman.

GET/webhooks/meta No auth

Meta's webhook subscription challenge. Echoes hub.challenge back if hub.verify_token matches META_WEBHOOK_SECRET, else 403.

POST/webhooks/meta HMAC signature

Receives comment and DM change events. Requires a valid X-Hub-Signature-256 header (HMAC-SHA256 of the raw body using META_WEBHOOK_SECRET, timing-safe compared) — invalid/missing signature returns 403.

Returns 200 immediately; matching against automation rules and enqueueing jobs happens fire-and-forget after the response is sent.

Internally this parses each entry.changes (comments) and entry.messaging (DMs) into normalized events, then calls ruleEngineService.evaluate() for each, in parallel.

Clerk lifecycle webhook — POST /webhooks/clerk (internal, hidden from this reference) keeps the local User table in sync with Clerk's user.created / user.deleted events, verified via Svix signature headers.
